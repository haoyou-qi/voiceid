# VoiceID：G2 聲紋辨識原型

用 Even Hub SDK 拿到的原始麥克風音訊，在手機上**即時辨識是誰在說話**，並把名字顯示在 G2 眼鏡上。
音訊全部在本機處理，不上傳、不需要網路。

## 功能

- **建檔**：對方自然說話 15 秒（最少 5 秒），建立他的聲紋檔（存在手機本機）
- **辨識**：每 0.5 秒判斷一次「最近 1.5 秒是誰在說話」，同一個結果連續出現 2 次才切換名字，避免畫面跳來跳去
- **陌生人判斷**：跟所有人都不像時，顯示「未知 / 不確定」
- **眼鏡操作**：單擊開始或暫停，雙擊離開
- **三種執行環境**：真機、模擬器、一般瀏覽器（用電腦麥克風）。沒有眼鏡也能完整測試

## 第一次執行（Windows / Mac 都可以）

需要先安裝 Node.js 20 以上。

```bash
cd g2-voiceid
npm install
npm install -g @evenrealities/evenhub-cli @evenrealities/evenhub-simulator
```

### 方法 A：一般瀏覽器（最快）

```bash
npm run dev
```

用 Chrome 開啟 http://localhost:5173 ，畫面右上角會顯示「瀏覽器模式」，用的是電腦麥克風。

### 方法 B：Even Hub 模擬器（模擬眼鏡畫面）

```bash
# 視窗 1
npm run dev
# 視窗 2
npm run sim
```

模擬器預設用電腦的預設麥克風。要換麥克風：

```bash
evenhub-simulator --list-audio-input-devices
evenhub-simulator --aid "<裝置名稱>" http://localhost:5173
```

### 方法 C：真的 G2（買了之後）

```bash
npm run dev
evenhub qr --url "http://<你電腦的區網IP>:5173"
```

用手機上的 Even Realities app 掃描 QR code。

## 建議的測試方式

1. 找 2~3 個人，每人用**同一支麥克風**建檔 15 秒
2. 開始聆聽，輪流說話，看「即時分數」區塊：
   - `ll`：模型分數，誰最高就最像誰
   - `z`：離本人基準線幾個標準差，0 附近代表很像，負很多代表不像
3. 再找一個沒建檔的人講話，看會不會正確顯示「未知」
4. 用兩個滑桿調整門檻：
   - 陌生人常被認成某人 → 把**陌生人門檻**調小
   - 本人常被判成未知 → 把**陌生人門檻**調大
   - 兩個人常互相認錯 → 把**最小差距**調大（會變得比較常顯示「不確定」）

## 程式結構

| 檔案 | 用途 |
|---|---|
| `src/dsp/fbank.ts` | Kaldi 相容的 80 維 fbank 特徵（CAM++ 用） |
| `src/dsp/campp.ts` | **CAM++ 深度聲紋模型**（主要方法） |
| `src/dsp/features.ts` | MFCC 特徵 + 語音偵測（VAD） |
| `src/dsp/speaker.ts` | GMM 傳統方法（模型載入失敗時的備援） |
| `src/dsp/ambient.ts` | 環境聲音：吵雜程度、聲音分類、警報 |
| `src/dsp/melspec.ts` | 環境聲音模型用的 64 維 log-mel 特徵 |
| `scripts/setup.mjs` | 安裝時自動複製 ONNX Runtime、下載兩個模型 |
| `src/dsp/engine.ts` | 即時引擎：滑動視窗、平滑、建檔流程 |
| `src/platform.ts` | Even SDK（眼鏡 / 手機麥克風、眼鏡顯示、觸控）和瀏覽器模式 |
| `src/main.ts` | 手機操作介面和眼鏡畫面 |
| `test/synth.test.ts` | 用合成人聲測試（`npm test`） |

## 辨識方法（v0.2）

主要使用 **CAM++**（阿里 3D-Speaker，20 萬中文語者訓練）深度聲紋模型，用 onnxruntime-web 在本機推論。
模型或 ONNX Runtime 載入失敗時，自動改用 MFCC + GMM 備援方法，頁面右上角會顯示目前用哪一種。

用公開的真人中文語音（4 位建檔者 + 1 位陌生人）跑完整即時流程的比較：

| 方法 | 已建檔者正確顯示名字 | 認錯人 | 陌生人判為未知 |
|---|---|---|---|
| GMM（門檻調整後） | 68% | 0 | 18/23 |
| **CAM++（2 秒視窗、門檻 0.42）** | **約 90%** | **0** | **23/23** |

沒顯示名字的時候會顯示「未知 / 不確定」，多半是剛開始說話、人聲還不到 0.6 秒的時候。

## 只顯示認識的人（過濾陌生人）

「即時字幕」區有一個開關，預設開啟：
- **開啟**：每句話說完後，用整句的聲紋判斷是誰說的；判定為陌生人的句子不會出現在字幕和眼鏡上（眼鏡標題顯示 `[濾]`）
- **關閉**：陌生人的話照樣顯示，標成「陌生人」
- 很短的句子（人聲不到 0.8 秒）資訊不夠，會保留並標「？」，避免把自己的「好」「嗯」刪掉

真人語音模擬對話（4 位建檔者 + 1 位陌生人輪流說話，14 句）：14/14 正確。

## 環境聲音（給聽障者的提示）

眼鏡第二行一直顯示環境狀態，例如 `吵[###-] 人聲吵雜 → 靠近+大聲`；聽到警報時改成 `!! 警笛聲 注意周圍 !!`（5 秒）。

- **吵雜程度**：安靜 / 普通 / 吵 / 很吵，依「說話空檔的背景音量」判斷，不受身邊說話聲影響。每支麥克風靈敏度不同，第一次請在一般音量的地方按「校正」
- **聲音種類**：用 CED-tiny（AudioSet 527 類、6MB）在本機分類：有人說話、人聲吵雜、有音樂、車聲／機器聲
- **人聲吵雜**：模型判斷有人群，或「有人聲但音量起伏很小」（多人聲音重疊時起伏 < 11 dB，一人說話通常 > 14 dB）
- **警報提醒**：警笛、喇叭、火災／煙霧警報、門鈴／電話、哭聲、尖叫、巨響；手機會震動並記錄在「警報紀錄」

模擬測試（安靜房間、一人說話、多人說話、背景音樂、說話＋音樂、警笛、煙霧警報）全部判斷正確。
限制：一個人在很吵的地方說話，也可能顯示「人聲吵雜」（建議一樣是大聲說）；真實的餐廳人聲沒辦法在測試環境模擬，請實際測試。

## 已知限制與下一步

- **建檔和辨識要用同一種音源**：眼鏡麥克風和手機麥克風的音色差很多，混用準確度會掉
- **兩人同時說話**：SDK 只給單聲道音訊，沒有方向資訊，重疊說話沒辦法拆開。陌生人和認識的人同時講時，那句字幕會標成認識的人
- **還沒在真機驗證的部分**：眼鏡的中文字型顯示、單擊事件的實際格式、觸控事件從 `textEvent` 還是 `sysEvent` 傳來，這些程式都已經做了相容處理，但要在模擬器或真機上確認
- **個資**：聲紋屬於生物特徵資料，建別人的聲紋檔前要先取得對方同意
